# The validation-code rule's corpus, read by ValidationCodeTest. Built on 2026-11-02 by the false-positive auditor
# (regles-faux-positifs-auditor), word by word as real senders write; then decided line by line.
#
# Format: id|C or L|text. C: the rule must take it for a validation code; L: it must not. {NBSP} and {NNBSP} stand for
# the French non-breaking spaces. A STOP shows only during a call or just after it: a false C costs a STOP then (and
# a text to the relative, D-015); a missed C, a code read out to a scammer. Every change of the rule adds its lines.
#
# Decided AGAINST the corpus's first verdict, on purpose:
# - C, though not one-time codes: O01 (RIO), O02 (PIN, PUK), O04 (voicemail) are tools of the scam itself (porting the
#   number, swapping the SIM, reading the voicemail); H02, R03: a withdrawal code — the bank's card-free withdrawal code
#   is a real one; B09, B10: a friend's "le code c'est 4821", which only the sender would tell apart; K11: an operation
#   code next to "virement", where the payment word wins, on the protective side.
# - L, known misses, rare: M04 ("48 29 13", in pairs), M05 (letters and digits), M10 ("482.913"), M27 (a code, then a
#   promo code in the same SMS: the promo vetoes the bare "code").
